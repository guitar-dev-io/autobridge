# Renderer lifecycle and session-state fixes

This pass verifies the latest self-drawn renderer and reconnect fixes. SELF_DRAWN stays lazy without a car output, Canvas access is serialized with in-repository surface release, touch mapping can use the renderer’s source snapshot, and the launcher writes a profile FPS target into renderer state. AUTO_MIRROR rebind recovery recreates only its output when the existing display update fails, while pipeline persistence rejects unavailable OWN_CONTENT. The remaining mismatches are at lifecycle and session-state boundaries. The personalDebug Kotlin compile and unit test task pass.

Watch for: **confirmed** stale surface-destroy callbacks still clear live screen-local input state; **confirmed** `SettingsStore.restore` can change the active pipeline behind `MirrorCoordinator`; **confirmed** projection startup or profile edits can leave the renderer without the selected app FPS; **confirmed** SELF_DRAWN counters survive a stopped session; **confirmed** the displayed drop count omits frames discarded inside `acquireLatestImage()`.

**Verdict**: NEEDS_CHANGES

## High-level view

The surface controller rejects null and non-current destroy callbacks, but `MirrorCarScreen` still performs disconnect and dimension-reset side effects afterward (**confirmed**). A replacement surface can remain attached while its input dimensions are zeroed and a disconnect timer is scheduled.

`persistScreenOffMode` is write-only, but the shared restore routine still assigns `ScreenOffController.pipelineMode` directly. Since `MainActivity` and `ProjectionService` call restore, opening the phone UI can bypass the coordinator’s live-projection guard (**confirmed**).

The launcher writes profile FPS only after app launch, while projection startup and settings restore clear the global target and the profile editor only updates disk. A profile selected before consent or changed during an active app therefore does not reliably reach the self-drawn throttler (**confirmed**).

Frame counters reset when a projection or capture engine starts, but not when the session stops; their `dropped` value covers renderer-side drops but not ImageReader’s internal latest-frame discards (**confirmed**).

<details>
<summary>Issues (5)</summary>

1. **Stale destroy clears live input state (confirmed)** — `MirrorCarScreen` resets dimensions, visible bounds, and disconnect state even when `MirrorSurfaceController` rejects a stale or null destroy callback. Propagate the controller’s acceptance result or gate those side effects on the current surface identity.
2. **Restore bypasses live pipeline ownership (confirmed)** — `SettingsStore.restore` directly assigns the pipeline while `MainActivity.onCreate` can run during a live projection, including when normalizing persisted OWN_CONTENT. Restore through the coordinator or leave the active pipeline untouched until the session ends.
3. **Profile FPS is lost across projection boundaries (confirmed)** — `ProjectionService.start`/`SettingsStore.restore` clear the runtime FPS and profile edits only update persistence, so a pre-consent launch or live profile change falls back to the vehicle/default rate. Rehydrate or update the active profile target instead of clearing it without replacement.
4. **SELF_DRAWN stats outlive the session (confirmed)** — Counters reset on attach/start but not on projection stop or pipeline transition, so the SELF_DRAWN UI can show a prior session as current. Reset on teardown/transition or label the values explicitly as the last session.
5. **Dropped-frame counter is incomplete (confirmed)** — `acquireLatestImage()` silently discards older queued images, while `dropped` increments only for pending replacement and later renderer failures. Count those source discards or label the metric as renderer-side/accepted-frame drops.

<summary>Details</summary>

### MirrorCarScreen still mutates state after stale surface destruction (confirmed)

`MirrorSurfaceController.onSurfaceDestroyed` rejects a missing identity and any callback whose `Surface` is not the current state surface at `MirrorSurfaceController.kt:55-63`. `MirrorCarScreen.onSurfaceDestroyed` then unconditionally calls `ProjectionService.onCarSurfaceDisconnected`, zeros `surfaceWidth` and `surfaceHeight`, and clears `visibleArea` at `MirrorCarScreen.kt:197-203`. If an old container arrives after a replacement, the coordinator keeps the replacement output, but subsequent clicks and gestures use zero dimensions and the disconnect grace timer is still armed. The identity gate must cover the screen-level side effects, not only the coordinator detach.

### SettingsStore.restore can switch a live renderer behind MirrorCoordinator (confirmed)

`persistScreenOffMode` no longer mutates runtime state, but `SettingsStore.restore` still assigns `ScreenOffController.pipelineMode` directly at `SettingsStore.kt:31-47`. `MainActivity.onCreate` invokes that routine at `MainActivity.kt:137-139`, including when the notification opens while `ProjectionService` and `MirrorCoordinator` still hold a projection. A restored AUTO/SELF_DRAWN difference, or the AUTO fallback for persisted OWN_CONTENT, can make `isSelfDrawnLocked()` disagree with the allocated producer: an AUTO display may be ignored as self-drawn, or a self-drawn engine may keep drawing after the coordinator switches to AUTO. Runtime restoration must use the same active-session guard as `setPipelineMode`.

### Projection startup clears the active app’s FPS target (confirmed)

`QuickAppLauncher.launch` copies `profile.preferredFps` into `MirrorSettings` at `QuickAppLauncher.kt:95-99`, but `ProjectionService.start` clears that value at `ProjectionService.kt:99-101`, and `SettingsStore.restore` clears it again at `SettingsStore.kt:53-55`. The profile editor at `MainActivity.kt:1405-1414` only saves the profile, so an app launched before capture consent loses a custom target, and changing the profile while the app is active does not update the renderer. `SelfDrawnMirrorEngine` consequently falls back to the vehicle/default target until the app is launched again; the active profile needs to be the throttler’s source of truth or be reapplied at session start and profile change.

### SELF_DRAWN diagnostics are not session-scoped (confirmed)

`MirrorCoordinator.attachProjection` and `SelfDrawnMirrorEngine.startBlocking` reset counters at `MirrorCoordinator.kt:176-179` and `SelfDrawnMirrorEngine.kt:109-110`, but `MirrorCoordinator.stopProjection` and `SelfDrawnMirrorEngine.stopBlocking` do not reset them. `MainActivity` displays the values whenever the selected mode is SELF_DRAWN at `MainActivity.kt:1674-1680`, even without an active projection or car surface. After stopping or detaching a session, the screen can present the previous session’s captured/rendered/FPS/latency values as current diagnostics.

### ImageReader latest-frame drops are not represented by the displayed counter (confirmed)

`SelfDrawnMirrorEngine.onImageAvailable` calls `acquireLatestImage()` before incrementing `captured` at `SelfDrawnMirrorEngine.kt:239-249`. Older queued images discarded by that API never reach `recordFrameDropped`; that counter is updated only when the pending image is replaced or a later render step rejects a frame at `SelfDrawnMirrorEngine.kt:256-258` and `287-348`. The developer UI labels the result simply `dropped` at `MainActivity.kt:1677-1680`, so it understates source loss without identifying it as renderer-side drops.
