# Opt-in self-drawn mirror pipeline and parked-only teardown

This change keeps `AUTO_MIRROR` as the default zero-copy path and adds an opt-in `SELF_DRAWN` pipeline that captures the consented default display through `ImageReader`, applies `RenderPlan` geometry, and draws to the Android Auto surface. `MirrorCoordinator` selects the producer before a session starts, while `OWN_CONTENT` remains rejected because the dedicated app-display path does not exist. The parking listener now tears down screen power and projection on both `MOVING` and `UNKNOWN`, and the UI/documentation preserve the explicit limitation that `SELF_DRAWN` does not guarantee screen-off survival. The local flavored unit tests and APK assemblies pass, but the new capture lifetime and reconnect error paths still need changes before shipping.

Watch for: **confirmed** `SELF_DRAWN` consumes ImageReader frames while no car surface is attached; **confirmed** a failed AUTO_MIRROR surface rebind stops the whole projection and forces a new consent flow; **likely** a null or out-of-order surface-destroy callback can invalidate a replacement; **confirmed** the existing per-app FPS preference never reaches the new renderer.

**Verdict**: NEEDS_CHANGES

## High-level view

`AUTO_MIRROR` still binds one OS-owned `VirtualDisplay` directly to the car surface, uses FIT for input alignment, and requires explicit MediaProjection consent. `SELF_DRAWN` adds app-owned geometry and frame accounting without claiming panel-off capture; `OWN_CONTENT` remains unavailable at restore, persistence, and attach time.

The self-drawn producer starts before a car output exists and remains active after detach, while a failed direct-surface rebind is escalated into projection teardown. The renderer has a generation check, but callback identity and Canvas-release ordering are not carried through the full surface lifecycle.

The parking listener now stops screen power and projection for both non-`PARKED` states, and the shared vehicle leases stop the service and leave the car app. The unresolved safety-adjacent issues are lifecycle races around a valid session, not a fail-open MOVING/UNKNOWN gate.

The settings fallback rejects unavailable `OWN_CONTENT`, but runtime mode mutation is split between `SettingsStore` and `MirrorCoordinator`; per-app FPS is not connected to the self-drawn target. Diagnostics and one lifecycle statement in `docs/MIRROR_ENGINE.md` also diverge from runtime behavior.

## Details

### SELF_DRAWN capture lifetime before a car surface (confirmed)

`MirrorCoordinator.attachProjection` creates and starts `SelfDrawnMirrorEngine` before `reconcileLocked()` checks whether a car surface exists. `SelfDrawnMirrorEngine.startBlocking` immediately allocates the `ImageReader`, capture and render `HandlerThread`s, and a capture `VirtualDisplay`; when `carSurface` is null, `reconcileLocked` returns `true` without attaching an output. The capture callback then continues accepting and replacing images even though `renderImage` can only count them as dropped because `output` is null.

The same behavior persists after `detachSurfaceBlocking`: it clears `output` and increments the generation, but does not pause or stop the reader/display. With `stopOnDisconnect` disabled, a phone can keep copying or dropping screen frames for the entire period that Android Auto is disconnected. Create or enable the producer only once a valid output exists, or explicitly pause and drain it on detach; projection consent can remain alive for reconnect without keeping an unconsumed capture pipeline hot.

### AUTO_MIRROR reconnects become projection failures (confirmed)

On an existing direct virtual display, `MirrorCoordinator.reconcileLocked` calls `resize()` and then assigns `existing.surface`. Any exception or failed operation releases the virtual display and returns `false`. The Boolean result flows through `MirrorSurfaceController.onSurfaceAvailable` to `MirrorCarScreen`, which calls `ProjectionService.onMirrorBindingFailed`; that marks the session failed, stops the projection, and discards the consent token.

A transient host resize or surface assignment failure therefore becomes a full session loss, even though the documented reconnect contract says a live projection should outlive a car surface and avoid fresh consent. Keep the MediaProjection alive while retrying or recreating only the output virtual display, and reserve service failure for an unrecoverable projection/capture error.

### Render generation ends before Canvas release (confirmed)

`SelfDrawnMirrorEngine.renderImage` checks the output generation and surface identity, but the check ends before `lockCanvas`. `MirrorCoordinator.detachCarSurface` then invalidates the output and immediately calls `Surface.release()`; a render worker that passed `stillCurrent` can race into `lockCanvas`, draw, or unlock after that release. The calls are wrapped in `runCatching`, so the race may appear as dropped frames rather than a crash, but the generation check does not guarantee that an old frame cannot use a replacement or released surface.

Coordinate detach with the render worker—either hold a render ownership token through lock/draw/unlock or wait for the worker to acknowledge the generation change before releasing the `Surface`.

### Surface destroy callbacks can invalidate a replacement (likely)

`MirrorSurfaceController.onSurfaceDestroyed` passes nullable `container.surface` to `MirrorCoordinator.detachCarSurface`, where `null` means “detach whichever surface is current,” and it resets `DisplayTransform` unconditionally. `MirrorSurfaceOwnership` prevents an old `MirrorCarScreen` instance from clearing a newer one, but it does not reject an old `SurfaceContainer` delivered to the same screen, and `SurfaceState.generation` never reaches the coordinator. If the host delivers a null or out-of-order destroy callback after a replacement, the current output can be detached or left attached with its safe/visible geometry reset. Gate destruction by surface identity/generation and do not use the wildcard detach form for a callback container.

### Fixed source geometry versus live phone input (likely)

`SelfDrawnMirrorEngine.startBlocking` samples the default-display width and height once and creates a fixed-size `ImageReader`/capture display. `OrientationMonitor` only observes rotation; it does not resize or restart that producer. `TouchRouter`, however, re-queries the live default-display dimensions for every gesture, while each `RenderPlan` uses the dimensions of the frame currently in the reader. If the phone rotates or its usable display size changes during a self-drawn session, pixels and touch coordinates can be based on different source geometries even though the static quarter-turn matrix is correct. Rebuild the capture on a source-size/rotation change, or make input use the renderer’s current source snapshot until the change is applied.

### Per-app FPS controls do not reach the renderer (confirmed)

`SelfDrawnMirrorEngine.targetFpsProvider` reads `RuntimeContextStore.context.value.vehicleProfile?.preferredFps` and falls back to 60. The existing per-app setting is `AppProfile.preferredFps`, changed by `MainActivity.cycleProfileFps` and persisted by `PerAppProfileStore`; `QuickAppLauncher` applies the profile’s scale and rotation but never passes its FPS to the renderer. Selecting 30 FPS for an app therefore has no effect in `SELF_DRAWN`, while the profile screen and mirror-settings text present that value as a renderer target. Wire the active app profile into the provider or remove/qualify the FPS control until it is implemented.

### Pipeline persistence can bypass coordinator lifecycle (likely)

`MirrorCoordinator.setPipelineMode` refuses a change while `projection != null`, but `SettingsStore.persistScreenOffMode` directly assigns `ScreenOffController.pipelineMode` before writing preferences. The current phone UI calls the guarded coordinator method first; the store API itself can still switch a live session without stopping or rebuilding its producer. A live AUTO virtual display can remain allocated while `isSelfDrawnLocked()` starts treating the session as self-drawn. Centralize runtime mutation in `MirrorCoordinator` and make persistence write-only, or apply the same active-session guard in the store.

### Frame stats after pipeline changes (confirmed)

`MirrorDiagnostics.resetFrameStats` runs when a self-drawn engine starts, but switching back to AUTO does not reset or tag those counters. `MainActivity.refreshStatus` prints captured/dropped/rendered/FPS/latency for every pipeline, so an AUTO session can display the last SELF_DRAWN session’s numbers as if they were current. `acquireLatestImage()` can also discard older available images internally, while `framesCaptured` counts only the returned image and `framesDropped` does not count those discarded buffers. Reset or namespace stats on pipeline/session transitions, label them as last SELF_DRAWN measurements, and define whether dropped counts include ImageReader-level discards.

### Unsupported OWN_CONTENT remains persisted (confirmed)

`SettingsStore.restore` maps an unavailable persisted `OWN_CONTENT` value to `AUTO_MIRROR`, and `persistScreenOffMode` refuses to write `OWN_CONTENT`, satisfying the fail-closed selection rule. The fallback is only in memory, though, so the unsupported enum remains in SharedPreferences and causes the fallback/log path again on every later restore. Normalize the stored value to AUTO if retaining the unsupported choice is not deliberate.

### Renderer scale contract in documentation (confirmed)

`docs/MIRROR_ENGINE.md` says changing “pipeline or scale” during an active projection is rejected. `setPipelineMode` is rejected in that state, but `setScaleMode` is allowed and the self-drawn renderer samples the updated `DisplayTransform` on later frames; the phone UI also exposes scale changes while SELF_DRAWN is active. Describe live scale updates in the documentation, or enforce the stated immutability in code.

### Tests stop at pure transforms (confirmed)

The passing JVM suites cover `DisplayTransform`, enum decoding, reconnect classification, and diagnostics formatting, but they do not exercise `RenderPlan.draw`, `SelfDrawnMirrorEngine` ImageReader/Canvas teardown, `MirrorCoordinator` mode selection or rebind failures, `MirrorSurfaceOwnership`, the parked listener, or the actual `SettingsStore.restore` fallback. The docs list DHU/device scenarios, but those are not execution evidence. Add pure matrix/geometry assertions and fakeable lifecycle tests where possible, plus instrumentation/device runs for ImageReader color order, surface replacement, orientation changes, and MOVING/UNKNOWN teardown before treating SELF_DRAWN as locally complete.
